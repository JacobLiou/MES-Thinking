# 06.4 制造证据链模型

> 所属篇章：06_CanWeProveIt 能否证明 ｜ 状态：⏳ 骨架（待填充）

## 本篇要回答的业务问题

- 记录了就等于能证明吗？从「有数据」到「可举证」差什么？
- 证据链的要素是什么：事件 → 记录 → 签名 → 时间 → 不可篡改？
- 数据完整性原则（ALCOA）如何在模型中落地？

## 1. 从记录到证据

<!-- 待填充：记录（Record）与证据（Evidence）的区别 -->

| 层次 | 说明 | 模型支撑 |
| --- | --- | --- |
| 事实 | 发生了什么 | ManufacturingEvent（05.1） |
| 记录 | 事实被固化，附时间与上下文 | TraceEvent / TestRecord |
| 签名 | 责任被归属到人 | 电子签名 / 审批（03.2 / 05.4） |
| 完整性 | 事后无法无痕篡改 | 审计日志 + 追加式设计 |

## 2. ALCOA 原则映射

<!-- 待填充：数据完整性（Data Integrity）检查项 -->

| 原则 | 中文 | 模型落点 |
| --- | --- | --- |
| Attributable | 可归因 | 事件携带操作员（5M1E - Man） |
| Legible | 清晰可读 | 结构化记录 + 原始报文保留 |
| Contemporaneous | 同步记录 | EventTime（发生时间）与记录时间分离 |
| Original | 原始 | RawPayload 原始报文 |
| Accurate | 准确 | 判定规则版本化（05.2） |

## 3. 审计与防篡改

<!-- 待填充 -->

- 审计范围：工单状态变更、手动放行、规则变更（对照 design.md §9.3）
- 追加式设计：事件不可修改，纠正 = 新事件（不覆盖旧记录）
- 哈希链 / 归档（长期演进方向，可选）
