# 08.4 MES 业务建模方法论

> 所属篇章：08_MES业务全景 ｜ 状态：✅ 已完成

## 本篇要回答的业务问题

- 总结这套建模方法：从六问到模型的操作步骤是什么？
- 面对新产品 / 新产线，如何复用此方法？
- 建模完成度如何检验？（检查清单）

## 1. 建模流程（六步法）

```mermaid
flowchart LR
    S1[①问六问<br/>圈定业务范围] --> S2[②识别对象<br/>定义层/执行层/记录层]
    S2 --> S3[③画状态机<br/>生命周期与合法流转]
    S3 --> S4[④定义事件<br/>事实+时间+5M1E上下文]
    S4 --> S5[⑤校验追溯<br/>正反向都能跑通]
    S5 --> S6[⑥对齐实现<br/>映射实体与API]
```

每步的输入、产出、参与者（业务 / 工艺 / IT）：

| 步骤 | 输入 | 产出 | 主导参与者 | 常见错误 |
| --- | --- | --- | --- | --- |
| ① 问六问 | 产品族、产线、一段真实流程 | 范围声明（做什么/不做什么） | 业务 + IT 共同 | 一上来讨论软件菜单而非业务范围 |
| ② 识别对象 | 范围内的名词清单 | 对象地图（00.4）：定义层/执行层/记录层/证明层 | 工艺 + IT | 把「页面字段」当「业务对象」 |
| ③ 画状态机 | 对象的生命周期描述 | 每个核心对象的状态机 + 不变量 | 工艺 + 质量 | 遗漏异常分支（Hold/返工）与终态 |
| ④ 定义事件 | 每个状态迁移的触发动作 | 事件清单 + 上下文（5M1E）字段 | 质量 + IT | 只存状态不存事件（追溯断链的根源） |
| ⑤ 校验追溯 | 事件与谱系数据设计 | 06.1 问题清单逐问验证 + 双向追溯演练 | 质量主导 | 只验证正向（查履历）漏掉反向（召回） |
| ⑥ 对齐实现 | 模型全套 | 实体表、API 契约、错误码映射 | IT 主导 | 实现偏离模型（Api 层写业务规则） |

六步是一次**收敛过程**：范围 → 结构（对象）→ 行为（状态）→ 事实（事件）→ 检验（追溯）→ 落地（实现）。顺序不可倒置——先画页面再补模型，正是 00.1 描述的失败路径。

## 2. 方法论要点

- **从「追溯问题清单」（06.1）反推模型完整性：回答不了的每问，都指向缺失的模型**。这是整个方法的自检引擎——比「功能清单打勾」严格得多，因为每个问题都对应可演示的数据查询。
- **先记录、再约束、后分析：模型先支持事实采集，再收紧约束（对应 M1→M2）**。新产线导入时同样适用：先让事件记全（哪怕不拦截），运行一段时间掌握真实流程后再上强制门控——用数据驯服流程，而不是用想象设计流程。
- **先小后大：单线体闭环验证后再横向复制（对应「先小后大」原则）**。第二个产品族的建模成本应该是「填参数」（新 BOM、新流程、新规格），而不是「改模型」——如果第二个产品族需要改模型，说明第一个的抽象有问题。
- **模型稳定性优先于功能丰富度**。宁可功能少而模型对，不可功能多而模型乱——功能是投影，模型是本体（00.1 §1）。

## 3. 建模完成度检查清单

逐项可打勾（全绿 = 模型可用于指导实现）：

- [x] 每个状态机都有终态，且终态不可逆（04.2 / 05.4）
- [x] 每次状态迁移都对应一个事件（可追溯）（05.1 / 08.3 INV-8）
- [x] 每个事件都携带 5M1E 上下文（03.4，按风险取舍并**声明**取舍）
- [x] 每个写操作都有幂等键（02.1 / 05.2 / 08.3 INV-3）
- [x] 反向追溯：任意 SN 可回答 17 问（06.1 清单，含实现状态标注）
- [x] 正向追溯：任意 Lot / 设备 / 模板可扩散到受影响 SN 集合（06.3）
- [x] 每个处置路径都有审批与留痕（05.4 §3）
- [x] 主数据（定义层）与过程数据（执行/记录层）分离（00.4 §1）
- [x] 错误码与业务规则一一对应（`MES-xxxx`，AGENTS.md 错误码表）

> 清单勾选状态说明：本目录文档已按模型层面完成自检（模型完备）；**系统实现**的对应完成度见各篇「与本仓库的对照」小节与 00.4 §3 映射表——模型全绿不等于实现全绿，两者的差距就是里程碑规划（见 §4）。

使用方式：新产品/新产线建模完成后跑一遍此清单；任何一项打不了勾，回到对应篇目补模型——**不要带病进入实现**。

## 4. 与本仓库里程碑的对应

| 里程碑 | 建模覆盖 | 对应篇目 |
| --- | --- | --- |
| M1 执行闭环 | 02 / 04 / 05.1–05.2 的最小集 | 工单、过站、上传、追溯 |
| M2 流程约束 + SPC | 02.2 / 04.3 / 05.3 完整化 | 防跳站、告警 |
| M3 追溯 + 看板 | 06 全部 + 08 全景 | 全链路追溯、实时看板 |

里程碑与建模的关系：**里程碑裁剪实现，不裁剪模型**。M1 只实现了模型的子集（TestFlow 承载 Routing、ProductCode 字符串化），但模型（00.4 对象地图）始终完整在册——这保证了 M2/M3 是「沿模型补齐」而非「重构」。反过来，若某能力在模型中不存在（如第一阶段的 APS），它就不该出现在任何里程碑里（`design.md` §2.2 Out of Scope）。

## 5. 适用与不适用

**方法适用边界**：本套方法（单件流、SN 中心、测试密集）最适合**离散制造单件流**——光通信器件、电子组装、医疗器械等。

| 制造形态 | 适用度 | 调整思路 |
| --- | --- | --- |
| 离散单件流（光通信/电子） | ★★★ 直接适用 | 本目录即为此建模 |
| 批量制造（批次处理为主，如烘烤、电镀） | ★★ 需调整 | SN 模型降级为 Lot 模型；Operation 状态机简化（整批 MoveIn/MoveOut）；追溯以批次谱系为主 |
| 流程制造（连续，如化工） | ★ 概念可借、模型需重建 | 六问与事件/证据思想仍适用；Routing → Recipe（ISA-88 批次控制）；本目录的对象模型大部分不适用 |
| 项目型制造（单台大型设备） | ★★ 需调整 | SN → 项目号（一台一生）；工序粒度变粗；谱系仍是核心 |

迁移口诀：**六问框架与「定义/执行/记录/证明」分层是通用骨架；SN 中心与状态机细节是单件流特化**——换制造形态时，保留前者、重做后者。
